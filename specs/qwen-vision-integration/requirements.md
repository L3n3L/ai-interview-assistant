# Qwen 视觉识图接入需求

## 1. 背景

当前 Qwen 模式已经通过 WebSocket 提供实时语音转写和文本回答，但截图入口在 `send-image-content` 中会直接返回“不支持截图”。本需求为 Qwen 模式新增独立的视觉 HTTP 请求链路，用于识别代码、算法题、报错信息和流程图。

视觉链路与实时语音链路并行存在，不替换、不重连、不改变现有语音会话。

## 2. 用户故事

- 作为使用中文面试助手的用户，我希望在 Qwen 实时语音模式下按截图快捷键后获得中文文字解答。
- 作为代码/算法题用户，我希望模型优先识别题目、代码、边界条件和复杂度，而不是只描述图片内容。
- 作为现有用户，我希望识图回答继续进入现有回答列表、三条分页和左右翻页快捷键。
- 作为问题排查人员，我希望日志能看到图片请求阶段、耗时、模型和响应大小，但不记录图片内容或 API Key。

## 3. 范围

### 包含

1. Qwen 模式下将截图发送给 `qwen3-vl-plus`。
2. 使用 Base64 `data:image/...` 作为图片输入。
3. 使用流式 HTTP 响应，复用 `new-response` / `update-response` 显示机制。
4. 开启视觉思考模式，并隐藏 `reasoning_content`，只展示最终答案。
5. 支持配置识图模型，默认 `qwen3-vl-plus`。
6. 记录可诊断的结构化日志。
7. 保存识图结果到现有屏幕分析历史。

### 不包含

1. 不把图片加入当前 Qwen 实时 WebSocket 会话。
2. 不修改当前 Qwen 语音模型、音频采集、VAD 或断句逻辑。
3. 不自动连续上传屏幕视频帧。
4. 不在日志中保存图片 Base64、完整请求体或密钥。
5. 不把完整内部思考过程展示给用户。

## 4. 验收标准（EARS）

1. **当**当前提供商为 Qwen 实时模式且用户触发手动截图，**系统应**将图片和中文算法分析提示词发送到配置的 Qwen 视觉模型。
2. **当**视觉模型返回第一段正式答案文本，**系统应**创建一条新的回答记录。
3. **当**视觉模型继续返回答案文本，**系统应**更新同一条回答，而不是创建多条碎片回答。
4. **当**视觉回答完成，**系统应**将其保存到屏幕分析历史，并使其参与现有三条分页和左右翻页。
5. **当**模型返回思考字段，**系统应**记录思考字符数量但不向界面展示思考内容。
6. **当**图片无效、Key 缺失、模型不可用、请求超时或返回错误，**系统应**显示可读错误并写入脱敏日志。
7. **当**用户使用实时语音，**系统应**保持原有 Qwen WebSocket 会话和语音回答行为不变。
8. **当**用户配置新的 Qwen 视觉模型，**系统应**持久化该配置并在下次启动时使用。

## 5. 约束

- API Key 仅在 Electron 主进程读取和使用。
- 图片请求必须使用可配置的 HTTP 端点，默认使用 DashScope OpenAI 兼容端点。
- 视觉回答默认中文、优先代码和算法解题。
- 当前实现继续使用现有回答事件，不引入第二套 UI 分页。
