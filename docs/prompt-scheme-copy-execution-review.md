# 提示词方案新增链路复盘

## 需求

新增方案只负责复制和登记：用户输入新名称后，复制当前编辑器中的提示词草稿，生成新的方案 ID，追加到本地方案列表，并把生效方案 ID 切到新方案。复制时不检查提示词是否完整、不填默认内容、不改原方案。

## 故障原因

新增按钮原来直接绑定了 Lit 点击回调：`@click=${this._addScheme}`。Lit 调用回调时会把点击事件作为第一个参数传入，而方法签名是 `_addScheme(importedPrompts = null)`。

因此点击“创建并切换”时，数据实际这样流转：

1. `importedPrompts` 收到 `MouseEvent`，而不是默认值 `null`。
2. `importedPrompts || pendingImportedPrompts || _draftPrompts` 选择了这个真值事件对象，当前草稿没有被选中。
3. JSON 深拷贝事件对象后，得到 `{ "isTrusted": true }`。
4. 该对象作为新方案的 `prompts` 写入本地 `preferences.json`，同时新方案 ID 被设为生效 ID。
5. 界面找不到 `profilePrompts[当前场景]`，所以隐藏场景的五个编辑区；自定义指令和简体中文要求是独立渲染的两个编辑区，因而只剩这两块。

此前的完整性检查只把这个错误挡成了笼统的“不完整”提示。移除检查但未修复事件参数后，错误对象就被成功写入。这是实现缺陷，问题不在用户提示词内容。

## 修复

- 点击按钮改用无参数包装函数，避免把 `MouseEvent` 传给创建方法。
- 提示词来源解析再识别并丢弃事件对象，按“显式导入内容、待导入内容、当前草稿”的顺序取值，防止以后再次直接绑定时复发。
- 新增时对选中的提示词数据做 JSON 深拷贝，不做完整性检查，也不补缺失字段或空字段。
- 原方案记录不变；新增方案只更新自己的名称、ID、时间和提示词副本。

## 本机数据恢复

本机新建的“开发”方案曾被写成只有 `isTrusted` 属性的对象。最近一场创建前的会话指纹与“运营岗-直播电商（对齐默认方案）”匹配，因此将“开发”的提示词数据恢复为该方案的完整副本。保留了“开发”的名称和 ID，也保留了恢复前当前生效方案 ID；没有打印或改写提示词正文。

## 验收

新增 `node:test` 单元测试，覆盖：

- 点击事件对象不会覆盖当前草稿。
- 显式导入内容优先于暂存导入内容和当前草稿。
- 待导入内容优先于当前草稿。
- 不完整对象会被深拷贝原样保留，不会被补齐或拒绝。
