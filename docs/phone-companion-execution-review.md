# 手机与电脑桥接：复盘执行文档

更新日期：2026-10-28

## 复盘结论

现有实现把“面试会话”和“手机网页服务”绑在一起：开始会话时才在随机端口启动服务，二维码 URL 还带每场随机路径；结束会话时关闭服务并断开 SSE。电脑与手机因此不能依赖同一个长期网页地址，刷新或下一场会话容易遇到旧页、旧快照或需要重新连接的问题。

回答列表由桌面渲染层和主进程桥各自维护。桥通过重复消费 `new-response`、`update-response` 等事件构造手机快照；事件缺少明确的场次归属，两个状态副本也增加了漂移机会。

另外，Cloud 模式使用了独立的 `sendToRenderer`，没有把回答事件送进手机桥；这会造成不同模型链路的手机同步行为不一致。

滚动同步把电脑位置换算成比例再应用到手机。电脑窗口和手机可视区域尺寸不同，比例不能表达“向下读一段”的业务意图；电脑没有可滚动空间时，手机也收不到有效滚动动作。

手机页目前包含标题、连接状态、回答标签、分页说明等外围信息。用户只需要看回答，并用一个按钮切换配色主题，这些外围信息不应占用屏幕。

## 目标与业务规则

1. 手机网页服务作为桌面应用的常驻本地桥接，与单场面试分开管理。固定端口、固定页面路由；同一台电脑和网络地址下，各场会话复用同一个 URL。应用退出时才关闭服务。电脑 IP 随网络变化时，地址列表/二维码随之更新。
2. 主进程维护当前手机镜像状态：`sessionId`、会话状态、回答列表、当前回答索引、状态版本号。它是桥接状态的唯一写入者；桌面和手机界面是消费者。
3. 每场开始时生成新 `sessionId`，清空本场实时回答和分页位置，并广播完整快照。回答事件带场次标识和递增版本；手机只处理当前场次的更新。结束时广播空的待机快照，但不关闭网页服务或 SSE。
4. 手机首次连接、刷新或重连时，服务先发送当前完整快照；手机整体替换本地回答状态，再处理后续增量，不能把新快照追加到旧回答上。
5. 桌面切换三条一组的回答分页时，同步当前回答索引到手机。电脑和手机各自持有滚动位置，互不发送滚动比例；切换会话或回答分页时，手机滚到本页顶部。
6. `Ctrl+↑/↓` 仍让电脑回答区按电脑自己的可视高度滚动，同时向手机发送 `up`/`down` 命令。手机按自己的可视高度执行一次滚动；手机触屏滚动只影响手机自身。普通电脑滚轮不远程控制手机。
7. 手机页面只呈现回答正文和右上角主题切换按钮。隐藏标题、连接状态、回答序号/标签、页码/分页指示、空状态文案及其他控件；无回答时页面留白，只显示主题按钮。
8. 音频采集、模型请求、回答生成与历史记录业务保持原样。手机桥只镜像模型最终产出的回答文字，不承接音频、转写、截图或密钥。

## 目标数据流

开始会话后，主进程创建新 `sessionId` 并重置桥接状态，向现有回答事件链路发布完整快照。模型链路照常处理音频并产出回答；回答新增、更新或撤销先进入主进程桥接状态，再发给桌面渲染层和手机 SSE。所有增量都带 `sessionId` 与版本号。

桌面翻页只更新共享的当前回答索引。电脑滚动只改变电脑自己的 `scrollTop`；快捷键另外产生一个方向命令，手机收到后以自身视口高度计算滚动距离。手机本地触摸滚动不回传电脑，也不改变桥接状态。

手机连接或重连时读取主进程当前快照；跨场次时以新快照整体替换旧状态。结束面试会清空当前镜像并广播待机快照，持续连接的手机显示空白回答区；下一场开始后同一页面地址收到新快照。

## 一次真实使用的数据走向

1. 桌面应用启动时，主进程在固定端口 `32147` 监听本地请求。比如电脑当前地址为 `192.168.1.20`，手机网页地址是 `http://192.168.1.20:32147/`。打开根路径返回的是空白回答页和主题按钮；SSE 连接后立即收到当前快照。
2. 第一场开始时，主进程生成场次 A 的 `sessionId`，把状态设为进行中，回答列表清空并广播完整快照。音频继续走原有模型链路，不经过手机桥。
3. 模型产出第一条回答时，主进程更新回答列表并发送带场次 A 标识和 `revision` 的 `response.new`。后续流式文本通过 `response.append` 或 `response.update` 到达。手机只渲染当前三条回答正文。
4. 用户在电脑按 `Ctrl+↓`：电脑回答区按电脑自己的高度滚动，同时主进程收到 `down` 指令并通过 SSE 发给手机。手机按自身视口高度滚动约 30%；电脑有没有剩余滚动距离，不影响手机消费这条指令。手机触屏滑动只改变手机位置。
5. 第一场结束时，主进程广播 `active: false`、空回答列表的快照，但 HTTP 服务和 SSE 连接保持。手机页面地址不变，正文清空。
6. 第二场开始时生成场次 B 的新 `sessionId`，广播第二场空快照。已有手机页立即切换到 B；即使用户刷新或网络短暂断线，重连时也会先取得 B 的完整当前快照，而不是把 A 的回答续接上来。
7. 电脑切换 `Ctrl+Left/Right` 回答组时，手机跟随三条分页并从该组顶部开始；电脑和手机的滚动位置之后各自独立。

电脑地址因 Wi-Fi/USB 网络切换而改变时，服务仍用同一个固定端口和根路由；二维码按新地址更新。原 IP 已不可达时，手机需要访问新地址，页面会通过新连接获取当前快照。
