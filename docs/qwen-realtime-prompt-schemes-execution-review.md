# Qwen 实时提示词方案执行复盘

## 目标

在现有“AI 定制”设置页开放 Qwen 实时语音实际使用的提示词，并允许用户管理多套命名方案。用户可以选择已有方案、修改并覆盖当前方案，或明确新增一套方案。保存当前方案不自动创建历史版本。

## 当前数据基线

- `src/utils/prompts.js` 定义 6 个既有场景；每个场景由 `intro`、`formatRequirements`、`searchUsage`、`content`、`outputInstructions` 五个既有字段组成。
- Qwen 实时语音通过 `getSystemPrompt(profile, customPrompt, false)` 生成正文，所以 `searchUsage` 字段保留，但按原逻辑不发送给 Qwen。
- 用户背景/自定义指令是现有 `customPrompt`；中文回答要求由 `getQwenSystemPrompt` 在中文语言设置下追加。
- 这些内容按原顺序拼成一个字符串，并作为一次会话配置中的 `instructions` 发给 Qwen。
- 当前“AI 定制”页只有场景选择和一个自定义指令框；程序没有提示词方案列表，场景模板与中文要求写在代码中。

## 已确认的方案操作

1. **选择已有方案**：从本机保存的方案列表中切换，完整加载该方案包含的所有提示词内容。
2. **修改当前方案**：编辑后点击“保存修改”，直接覆盖这套方案当前内容，不自动产生 v2 或历史记录。
3. **新增提示词方案**：用户填写新方案名称并点击新增，程序把当前编辑内容复制为另一套独立方案；新增才会增加方案记录。
4. **全量保存**：一套方案保存全部场景模板字段、自定义指令和 Qwen 中文回答要求；不按字段拆成多份档案。
5. **沿用现有结构**：场景选择、各个代码字段、提示词拼装顺序、Qwen 实时音频链路均保留。
6. **链路边界**：只有 Qwen Realtime / Qwen Omni 实时语音读取选中的方案；DeepSeek、本地 AI、Gemini 等链路继续走现有提示词构造。
7. **不增加会话留档**：本次不在每场历史会话里另存整套提示词或方案历史；提示词方案只保存在本地设置中。
8. **删除方案**：用户可删除当前非默认方案；确认后从方案列表移除，并把当前方案切回“默认方案”。“默认方案”不能删除。

## 本地数据形态

在现有 `preferences.json` 中增加：

- `qwenPromptSchemes`：方案列表。每条包含 `id`、用户名称、创建/修改时间，以及整套提示词内容。
- `activeQwenPromptSchemeId`：当前选中的方案。

第一次读取时，从现有代码模板和已保存的 `customPrompt` 创建“默认方案”。不修改或清空已有背景内容。旧版默认方案会改名为“默认方案”；如果模板仍是未编辑的初始内容，则升级为中文模板，同时保留已有自定义指令。后续保存当前方案只替换该方案的内容；新增方案才追加一条独立记录。

## 文件导入与导出

- 导出当前方案为可编辑的 JSON 文件，包含方案名称和原有完整提示词字段，便于交给其他 AI 编辑。
- 导入 JSON 会直接新增一套方案并切换为当前方案，不覆盖已有方案。
- 文件中的方案名称用作新方案名称；若已重名，界面保留导入内容并要求改名后创建，不自动生成 v2 名称。
- 导入文件需保留所有原有场景和字段；格式错误时显示原因，不改动已保存方案。

## 编辑页布局约束

- 方案选择不使用独立卡片或大容器；方案下拉框、导入、导出、新增放在同一行。
- 只有新增或导入遇到重名时才显示方案名称输入行。
- 首次读取方案后，在选项渲染完成时按已保存的当前方案 ID 同步下拉框，避免显示回落到第一项。
- 整个设置页使用一个纵向滚动区，所有提示词字段从上到下连续排列；文本框随着内容自动增高，避免再出现文本框内部滚动条。
- 编辑区使用可用的完整宽度。回答内容与示例、用户自定义指令提供更大的初始编辑高度，其他字段也按用途分配高度。

## 数据流

1. 打开现有“AI 定制”页时，从本地偏好文件读取方案列表和当前方案；首次迁移时生成默认方案。
2. 用户选择一个既有方案，设置页加载它的完整提示词内容；Qwen 实时会话将使用当前选中的方案。
3. 用户修改内容后点击“保存修改”，程序定位当前方案 ID 并替换整套内容，其他方案不变。
4. 用户要另做一套时，填写新名称并点击“新增提示词方案”；程序复制当前编辑内容，分配新的方案 ID，并把新方案设为当前方案。
5. 开始 Qwen Realtime / Qwen Omni 会话时，Renderer 读取当前已保存方案，校验全部六个场景及字段后，只把当前方案 ID 传给主进程。
6. 主进程重新读取本地偏好文件，并核对传入 ID 与磁盘上当前方案 ID 完全一致，再要求该 ID 唯一命中并二次校验。若读取期间方案刚被切换、ID 不存在、重复或字段不完整，立即中止启动，不改用默认方案或其他方案。
7. 主进程从已核对的方案中取所选场景模板、自定义指令和中文要求，按现有顺序生成一段 `instructions`，沿用原有 `session.update` 发给千问一次。
8. 后续系统音频/麦克风音频分片、转写事件和回答事件继续走原有实时链路。

## 实施范围

- 在本地偏好存储中初始化和保存完整提示词方案。
- 在现有 AI 定制页开放原有模板字段，添加方案选择、覆盖保存和显式新增方案操作。
- 支持删除当前非默认方案；删除后自动切回默认方案，默认方案不可删除。
- 将方案管理收紧为单行工具栏，并让提示词字段使用页面级滚动和更充足的编辑空间。
- 让 Qwen Realtime / Omni 使用当前方案；非 Qwen 链路保持原有提示词来源。
- 不新增自动修订历史、版本编号或会话提示词存档。

## 验收标准

- When 用户首次打开提示词设置且本地没有方案时，程序 shall 从现有模板和已保存背景内容建立默认方案。
- When 用户选择已有方案时，程序 shall 加载该方案完整内容并设为 Qwen 当前方案。
- When 用户点击保存修改时，程序 shall 覆盖当前方案内容且不新增方案记录。
- When 用户填写名称并点击新增方案时，程序 shall 创建独立方案并复制当前编辑内容。
- When 用户删除非默认方案时，程序 shall 在确认后移除该方案并切回默认方案；程序 shall 禁止删除默认方案。
- When Qwen Realtime 或 Qwen Omni 开始会话时，程序 shall 用当前方案按原顺序组装一段 `instructions` 并发送。
- When Renderer 传入的方案 ID 与主进程重新读取到的当前 ID 不一致时，程序 shall 停止启动且不得回退到默认方案或其他方案。
- When 使用非 Qwen 模型时，程序 shall 保持现有提示词构造路径。

## 实施结果

- “保存修改”只更新当前方案原记录；“新增提示词方案”才会新增一条方案。
- 删除非默认方案前会确认，提示未保存修改；删除后重新加载并切回默认方案。
- 默认方案的删除按钮保持禁用。
- 不生成 v2、自动修订历史或逐会话提示词快照。
- 切换方案前若当前有未保存修改，界面会要求先保存或新增，避免编辑内容被切换操作丢弃。
- Renderer 与主进程都校验当前方案；主进程按方案 ID 从最新本地偏好重新读取，避免旧对象或并发切换把另一套方案带入会话。
- 方案保存与切换在磁盘写入失败时返回失败状态，界面不会把未持久化的选择当作成功。
- 仓库没有自动化测试套件；本轮执行了格式、语法和打包检查，未做真实 Qwen API 面试联调。
